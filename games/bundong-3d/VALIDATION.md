# Meshy 모델 적용·검증 기록

검증일: 2026-10-10. 브랜치: `claude/upbeat-hypatia-m5gnyz`.

## 변경 사항

- 학생 사진 2장을 Meshy 7로 생성하고 뼈대·기본 걷기를 적용. `assets/players/models.json` 등록.
- 유물 7점을 Meshy 6 설명문 기반으로 생성하고 `assets/relics/manifest.json` 등록.
- 학생·걷기·유물 GLB 11개를 최대 2K 텍스처, 10,000,000바이트 이하로 최적화. 뼈대·정점·애니메이션 데이터 유지. 유료 리메시·재생성 없음.
- 생성·뼈대 작업 비용은 사용자 승인한 280크레딧. 잔액 692 → 412. API 키를 파일에 저장하지 않음.
- 친구는 기존 위치 주변 2.4m 구간을 초속 0.65m로 이동. 4.5m 이내에 오면 멈추고 플레이어를 바라봄. 대화 위치·충돌체도 갱신.
- 걷기 GLB의 뼈대와 클립을 함께 사용. 정지 시 팔은 내리고 다리·골반은 기립 자세 유지. 크기·방향 보정 그룹과 애니메이션 대상을 분리.
- 학생 표면의 금속 반사와 작은 UV 조각의 밉맵 경계 흰 점 보정.
- `relics.js`의 `holdGLB`로 검의 시야 가림, 곡옥 방향·크기, 해시계 받침 위치 조정. 기본 모델 자세 유지.
- `dist/bundong3d.html` 갱신. 내 몸·시점 팔은 기존 절차적 모델 유지.

## 확인한 것

JS 모듈 전부 `node --check` 통과, esbuild 단일 HTML 빌드 및 `git diff --check` 통과.
Edge 브라우저의 `?test=1&quality=medium`에서 Intel UHD Graphics / Direct3D11 실제 GPU를 사용.

- 학생 2명·유물 7점 로딩. 최종 검사에서 페이지 오류와 에셋 다운로드 오류 없음.
- 남학생·여학생 정지와 걷기 스크린샷. 키 1.72m / 1.64m, 걷기 클립 바인딩 정상.
- 친구는 테스트에서 1초간 0.65m 이동, 동작 시간 진행. 모델·대화·충돌 좌표 일치, 접근 시 정지.
- E키 친구 대화, W키 이동, F키 손전등, I키 가방, M키 지도.
- 반닫이 획득 동작 뒤 첫 유물·악령·퀘스트 시작. 일곱 유물 수집 이벤트 뒤 봉인석 단계 진입.
- 유물 7종 스킬 실행 및 재사용 대기, 향로 GLB 정화 구역.
- 날씨 6종 전환, 낮·밤 조명, 저장 뒤 새로고침·이어하기의 선택 성별·이름·유물·퀘스트·날씨 복원.
- 모든 유물의 장착 완료 후 손 위치를 스크린샷으로 확인.
- `file://`로 단일 HTML 직접 실행, 학생 선택·시작 및 기본 모델 대체 정상.
- Web Audio 초기화 및 오디오 컨텍스트 `running` 상태.

퀘스트와 날씨 검사의 일부는 `window.__game` 테스트 훅을 이용했습니다. 전체 게임을 처음부터 끝까지 플레이한 검증은 아닙니다.

## 아직 확인하지 못한 것

- 보스전 전체 완주, 모든 상자·문·제작 조합, 장시간 성능 및 학교의 여러 기기·브라우저.
- 실제 스피커를 통한 소리 청취, 휴대폰·태블릿(터치 조작 미지원).

- 학생 옆·뒤 모습의 일치. 현재 입력은 정면 사진 1장씩.
- REST 대체 생성 스크립트의 실제 API 호출.
